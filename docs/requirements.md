# KBO 응원가 즉시 재생 웹서비스 요구사항 정의서

- 과목: 2026-2학기 스크립트프로그래밍 / 작성: 20241476 김도훈 / 작성일: 2026-11-15
- 단계: STEP 1 요구사항 분석 (최종본), STEP 2 설계 검토 결과로 업무 규칙·예외·알려진 한계 갱신(12절)
- 기술 환경: React, TypeScript, Vite, LocalStorage, YouTube IFrame Player API, YouTube Data API v3

## 1. 서비스 개요

### 1.1 서비스 설명

친구들과 야구 게임(MLB The Show)을 할 때, 타석에 선 선수의 응원가와 경기 상황에 맞는 응원가를 버튼 한 번으로 트는 웹서비스다. 음원 파일은 두지 않고 YouTube 영상의 특정 구간을 재생한다. 곡 하나는 "영상 ID + 시작 시각 + 끝 시각(+ 응원가 시작 지점)"으로 정의한다.

### 1.2 개발 목적

- 게임 중 응원가를 찾느라 흐름이 끊기지 않게, 열자마자 쓰던 팀 화면이 나오고 한 번 누르면 바로 재생되게 한다.
- 팬 채널이 올린 구단별 응원가 모음 영상의 챕터(설명란 타임스탬프)를 그대로 곡 목록으로 바꿔, 직접 시각을 받아 적지 않고 곡을 등록한다.
- 수업 과제 필수 요소(등록·수정·삭제·검색, useState·useEffect, 반응형 UI, 외부 Open API)를 실제 쓰임이 있는 서비스로 구현한다.

### 1.3 사용자와 사용 환경

| 구분 | 내용 |
| --- | --- |
| 사용자 | 야구 게임을 하며 응원가를 트는 사람 1명(방장). 로그인 없음 |
| 기기 | 노트북 브라우저, 휴대폰 브라우저(세로 화면) |
| 실행 방식 | 공개 주소 `https://kbocheer.kdhoon.me`(Cloudflare Workers 정적 자산)로 노트북과 휴대폰 모두 접속한다. 개발할 때는 노트북에서 개발 서버(포트 5173)를 돌려 `http://localhost:5173`으로 열고, 휴대폰은 같은 와이파이에서 노트북의 LAN 주소(예: `http://192.168.0.10:5173`)로도 열 수 있다 |
| 사용 상황 | 게임 화면을 보면서 짧은 순간에 눌러야 한다. 한 경기 동안 두 팀을 번갈아 쓴다 |
| 데이터 | 각 브라우저의 LocalStorage에만 저장. 서버·DB 없음. 기기 사이 이동은 JSON 파일로 한다 |

### 1.4 용어

| 용어 | 뜻 |
| --- | --- |
| 모음 영상 | 한 구단의 응원가를 이어 붙인 YouTube 영상. 설명란에 `MM:SS 제목` 형식 타임스탬프가 있다 |
| 챕터 | 설명란 타임스탬프 한 줄이 가리키는 구간 |
| 선수 응원가 | 선수 한 명의 곡. 등장곡만 있거나, 등장곡 뒤에 응원가가 이어진다 |
| 응원가 시작 지점 | 선수 곡 안에서 등장곡이 끝나고 응원가가 시작하는 시각(cheerStart) |
| 팀 응원가 | 구단 공통 응원가(예: "외쳐라 이글스") |
| 상황 곡 | 경기 상황에 트는 곡(예: 풀카운트 송, 볼넷 송, 공통 안타 송, 라인업송) |
| 주전순 | 올 시즌 타석 수가 많은 순서. 자주 나오는 선수가 앞에 온다 |
| 선수 기록 | 선수의 포지션, 경기·타석 수, 사진 유무를 담은 번들 데이터(`src/data/players-2026.json`, KBO 기록실 2026 정규시즌 기준) |
| 현재 팀 / 전 팀 | 지금 화면의 팀 / 바로 전에 보던 팀 |
| 처음 데이터 | 앱에 함께 넣어 두는 10개 구단 곡 목록 JSON. 저장 데이터가 없을 때와 「처음 데이터로 되돌리기」에 쓴다 |

### 1.5 원본 데이터 조사 결과 (2026-11-15, YouTube Data API `videos.list`로 10개 영상 확인)

요구사항의 근거로 실제 설명란 구조를 확인했다.

| 항목 | 확인 결과 |
| --- | --- |
| 영상 | 10개 모두 같은 채널(놀맘댈)의 "26.09 ver" 모음 영상, 길이 52~70분, 10개 모두 퍼가기(embeddable) 허용 |
| 타임스탬프 형식 | `MM:SS 제목`, 1시간 넘는 영상은 `H:MM:SS 제목`. 일부 줄 끝에 공백 있음 |
| 시각 순서 | 10개 영상 모두 앞 줄보다 시각이 같거나 작은 줄을 검사했다. **두산 영상(jHxEtjKhJvA) 1줄만 거꾸로 간다**: `39:15 챔피언 두산` 다음 줄이 `30:36 서울 두산 승리하리라`이고, 그다음은 `42:05 해야`다. 실제 시각은 39:15와 42:05 사이로 보이는 오타다. 나머지 9개 영상은 0건 |
| 구획 | `-----` 구분선으로 2~3개 구획. **마지막 구분선 뒤는 항상 팀 응원가**(구단별 17~29곡) |
| 선수 곡 | 제목이 `<이름> 등장곡+응원가` 또는 `<이름> 등장곡`으로 끝난다. 이 두 형식에서 벗어난 선수 제목은 없다. 10개 구단 합계 235명, 그중 등장곡만 있는 선수 16명 |
| 상황 곡 | 선수·팀 구획 밖의 나머지. 풀카운트 송, 볼넷 송(롯데는 "볼넷송"), 공통 안타 송, 라인업송, 경기 개시 음악 등. 구단 고유 곡(체로키, 셀리오, 환희, 시그널 등)도 섞여 있다 |
| 중복 | "공통 안타 송"이 한 영상에 1~4번 반복된다(등장곡만 있는 선수 뒤에 붙음) |
| 없는 정보 | 응원가 시작 지점은 설명란에 없다. 상황 곡은 영상마다 구성이 다르다 |

## 2. 사용자 관점 기능 도출

| 사용 장면 | 필요한 기능 |
| --- | --- |
| 앱을 열면 마지막으로 쓴 팀 화면이 바로 나온다 | 팀 선택, 마지막 팀 기억 |
| 타자가 나오면 선수 격자에서 이름을 누른다 | 선수 격자, 선수 곡 재생, 격자 정렬 |
| 등장곡 다음 응원가가 나오고 「응원가로」로 건너뛴다 | 구간 재생, 응원가 시작 지점으로 이동, 응원가 시작 지점 지정 |
| 풀카운트·볼넷·안타 같은 상황에 버튼을 누른다 | 상황 버튼 재생 |
| 상대 팀 차례면 「전 팀」으로 바꾼다 | 전 팀 전환, 구단 로고로 팀 구분 |
| 격자에 안 보이면 초성이나 이름으로 검색해 바로 튼다(상대 팀 선수 포함) | 10개 구단 전체 곡 검색, 검색 결과 재생 |
| 노트북으로 게임하며 손을 떼지 않고 조작한다 | 키보드 단축키 |
| 게임 소리와 응원가 크기를 맞춘다 | 볼륨 조절, 페이드아웃 |
| 모음 영상 URL을 넣어 곡을 등록한다 | 설명란 읽기(Data API), 챕터 분석, 확인 후 저장 |
| 영상 하나짜리 URL이나 검색으로 곡을 추가한다 | 단일 영상 등록, YouTube 검색 등록 |
| 잘못된 시각이나 이름을 고친다, 필요 없는 곡을 지운다 | 곡 수정, 곡 삭제, 처음 데이터로 되돌리기 |
| 노트북에서 만든 곡 목록을 휴대폰에서 쓴다 | JSON 내보내기·가져오기, 휴대폰 접속 안내 |
| 폰과 노트북에서 쓴다 | 반응형 화면 |

## 3. 기능 요구사항

| ID | 기능 | 상세 설명 | 과제 필수 요소 |
| --- | --- | --- | --- |
| FR-01 | 팀 목록·선택 | KBO 10개 구단을 고르는 팀 선택 메뉴를 제공한다. 고른 팀의 곡만 화면에 표시한다 | useState |
| FR-02 | 마지막 팀 복원 | 마지막으로 본 팀과 그 전 팀을 저장하고, 앱을 열면 마지막 팀 화면을 바로 보여 준다 | useEffect, LocalStorage |
| FR-03 | 전 팀 전환 | 「전 팀」 버튼으로 현재 팀과 전 팀을 맞바꾼다 | |
| FR-04 | 선수 격자 | 현재 팀의 선수 곡을 이름 버튼 격자로 보여 준다. 기본 순서는 주전순(FR-27)이다 | 반응형 UI |
| FR-05 | 선수 곡 재생 | 선수 버튼을 누르면 그 곡의 시작 시각부터 재생하고 끝 시각에 멈춘다 | Open API(IFrame) |
| FR-06 | 응원가로 건너뛰기 | 선수 곡 재생 중 「응원가로」를 누르면 응원가 시작 지점으로 이동한다 | |
| FR-07 | 상황 버튼 | 현재 팀에 등록된 상황 곡을 화면 아래 4×2 상황 칸(안타·아웃·볼넷·풀카운트 / 라인업·라인업 소개·경기 개시·기타)으로 보여 주고, 누르면 재생한다. 같은 상황은 팀이 바뀌어도 같은 칸이고, 곡이 없는 칸은 비워 둔다. 같은 상황의 두 번째 곡은 다른 상황의 칸을 쓰지 않고 4×2 아래에 더한 줄에 놓는다. 칸에는 상황 이름(안타, 볼넷, 풀카운트, 라인업 등)을 크게 쓰고, 이름만으로 어느 곡인지 알 수 없을 때만 곡 제목을 그 아래 한 줄에 작게 쓴다. 기타 칸은 곡 제목을 크게 쓴다 | |
| FR-08 | 팀 응원가 목록 | 현재 팀의 팀 응원가를 목록으로 보여 주고, 누르면 재생한다 | |
| FR-09 | 재생 상태·정지 | 지금 재생 중인 곡 이름(다른 팀 곡이면 팀 이름 포함)을 표시하고 「정지」 버튼으로 멈춘다. [STEP 3-㉑] 플레이어를 직접 눌러 멈추면 그 곡의 일시정지로 보이고 「이어서」로 멈춘 자리부터 튼다(BR-62) | |
| FR-10 | 곡 검색 | 검색칸에 이름·제목 또는 초성(예: ㄴㅅㅎ → 노시환)을 치면 10개 구단 전체 곡에서 찾는다. 현재 팀 결과를 먼저, 다른 팀 결과는 팀 이름을 붙여 뒤에 보여 준다. 결과를 누르면 바로 재생하고, 다른 팀 곡이면 그 팀으로 바꾼 뒤 재생한다 | 검색 |
| FR-11 | 모음 영상 가져오기 | 모음 영상 URL을 넣으면 Data API로 제목·설명란·길이를 읽고, 챕터마다 곡 후보(종류·이름·시작·끝)를 만든다 | 등록, Open API(Data) |
| FR-12 | 가져오기 확인·저장 | 곡 후보를 표로 보여 주고, 사용자가 종류·이름·시작 시각을 고치거나 뺄 곡의 선택을 풀고 「저장」해야 등록된다. 시각이 거꾸로 가는 줄은 경고와 함께 표시한다. [STEP 3-⑰] 가져오기(FR-11~14)는 곡 관리 화면의 「곡 추가」로 들어가고, 저장하거나 취소하면 곡 관리 목록으로 돌아온다. 화면 메뉴는 응원 · 곡 관리 · 설정이다 | 등록 |
| FR-13 | 단일 영상 등록 | 챕터가 없는 영상 URL을 넣으면 영상 전체(0초 ~ 영상 길이)를 곡 하나로 등록한다. 사용자가 종류·이름·시각을 입력한다 | 등록 |

| FR-15 | 곡 수정 | 등록된 곡의 이름, 종류, 시작·끝 시각, 응원가 시작 지점을 고친다 | 수정 |

| FR-17 | 데이터 저장·유지 | 곡 목록, 팀 상태, 설정(볼륨, 격자 정렬)을 LocalStorage에 저장하고, 새로고침 후에도 유지한다 | useEffect, LocalStorage |

| FR-19 | 지금을 응원가 시작으로 | 선수 곡 재생 중 「지금을 응원가 시작으로」를 누르면 현재 재생 시각을 그 곡의 응원가 시작 지점으로 저장한다 | 수정 |

## 5. 업무 규칙

### 5.1 재생

| ID | 규칙 |
| --- | --- |
| BR-01 | 한 번에 한 곡만 재생한다. 다른 곡 버튼을 누르면 지금 곡을 페이드 없이 바로 멈추고 새 곡을 시작한다(응답성 우선) |
| BR-02 | 곡은 시작 시각부터 재생하고, 끝 시각에 이르면 멈춘다 |
| BR-03 | 재생 중인 곡의 버튼을 다시 누르면 처음(시작 시각)부터 다시 재생한다 |
| BR-04 | 「응원가로」는 재생 중인 곡이 응원가 시작 지점이 있는 선수 곡일 때만 누를 수 있다. 그 밖에는 비활성이다 |
| BR-05 | 응원가 시작 지점이 없는 선수 곡(등장곡만 있거나 아직 지정하지 않은 곡)은 시작부터 끝까지 그대로 재생한다 |
| BR-06 | 팀을 바꿔도 재생 중인 곡은 멈추지 않는다(상대 팀 화면으로 넘어가며 곡을 끊지 않기 위해) |
| BR-07 | 「지금을 응원가 시작으로」는 재생 중인 곡이 선수 곡이고 현재 재생 시각이 시작 < 시각 < 끝일 때만 누를 수 있다. 저장 값은 초 단위로 내림한다. 이미 지점이 있으면 덮어쓴다 |

### 5.2 곡 등록

| ID | 규칙 |
| --- | --- |
| BR-08 | 등록은 "URL 입력(또는 검색 결과 선택) → 후보 확인 → 저장" 순서다. 확인 단계에서 「저장」하기 전에는 아무것도 저장하지 않는다 |
| BR-09 | URL은 `youtube.com/watch?v=`, `m.youtube.com/watch?v=`, `youtu.be/`, `youtube.com/shorts/`, `youtube.com/embed/` 형식과 11자리 영상 ID만 받는다. `&pp=`, `&t=`, `&list=`, `?si=` 같은 추가 값은 무시하고 영상 ID만 쓴다(`t`로 시작 시각을 정하지 않고, `list`의 재생목록은 읽지 않는다) |
| BR-10 | 설명란에서 `[H:]MM:SS 제목` 형식의 줄만 챕터로 쓴다 |
| BR-11 | 후보의 시작 시각(사용자가 고친 값 포함)이 설명란 순서대로 엄격하게 증가하지 않는 줄은 "시각 이상"으로 표시하고 저장 대상에서 뺀다. 어느 줄이 이상인지는 시각이 증가하는 가장 긴 부분열에 들지 못한 줄로 정한다(이상 줄 수가 가장 적게). 시각을 해석할 수 없거나 영상 길이 이상인 줄도 시각 이상이다. 사용자가 시각을 고쳐 순서가 맞으면 정상 후보가 되어 저장 대상이 된다 |
| BR-12 | 곡의 끝 시각은 시작 시각이 더 큰 다음 정상 챕터의 시작 시각이다. 정상 챕터에는 저장하지 않는 줄(중복, 선택 해제)도 들어가고 시각 이상 줄은 빠진다. 마지막 곡은 영상 길이다. 그래서 앞 곡의 끝 시각이 시각 이상 줄 때문에 줄어들지 않는다. 시각을 고치면 끝 시각을 다시 계산한다 |
| BR-13 | 곡 종류 자동 분류는 다음 순서로 적용한다: 마지막 `-----` 구분선 뒤 = 팀 응원가, 그 밖에서 제목이 `등장곡` 또는 `등장곡+응원가`로 끝남 = 선수 곡(이름은 그 앞부분), 나머지 = 상황 곡. 사용자는 확인 단계에서 종류를 바꿀 수 있다 |
| BR-14 | 한 팀 안에서 제목(공백·대소문자 무시)이 같은 상황 곡은 하나만 저장한다. 팀에 이미 같은 제목이 있으면 후보는 모두 "중복", 없으면 시각 이상이 아닌 첫 후보만 남기고 나머지는 "중복"으로 표시해 선택할 수 없게 한다(예: 공통 안타 송 4번 → 1곡). 후보의 종류·이름·시각을 고칠 때마다 다시 판정한다 |
| BR-15 | 가져오기는 현재 팀에 추가한다. 같은 영상 ID와 같은 시작 시각(지금 후보 값 기준)의 곡이 그 팀에 이미 있으면 후보에서 "이미 있음"으로 표시하고 기본으로 선택을 풀어 둔다 |

| BR-59 | 가사는 곡(팀·영상·시작 시각이 같은 곡)마다 하나다. 가사 413곡(팀 응원가 192, 선수 189, 상황 32)은 AI 코딩 에이전트(Claude Code)가 나무위키 구단별 응원가 문서에서 모았다(CC BY-NC-SA 2.0 KR, 곡마다 문서 주소를 둔다). 사진과 같이 공개 저장소와 `public/`에 넣지 않고, 가사 파일이 있는 실행(`media-build/lyrics`가 있는 개발 서버, `npm run build:deploy`)에서만 요청한다. 한 팀의 곡을 그 화면을 연 뒤 처음 틀 때 그 팀 파일 하나만 받고, 받은 파일은 다시 받지 않는다. 가사 칸은 처음에 접혀 있고, 펼친 상태는 곡이 바뀌어도 유지한다(저장하지 않음). 가사 아래에는 늘 출처 문서 링크와 라이선스를 쓴다 |

### 5.11 플레이어를 직접 눌렀을 때 [STEP 3-㉑]

| ID | 규칙 |
| --- | --- |
| BR-62 | 플레이어가 멈춘 이유를 넷으로 나눈다: 앱이 멈춤(정지·곡 바꾸기), 불러온 직후 이전 곡에서 남은 신호, 끝 시각에 닿음, 밖에서 멈춤(플레이어를 직접 누름, 전화 등). 밖에서 멈추면 곡 구간을 지우지 않고 일시정지로 보인다. 재생 줄·지금 재생 시트에 「일시정지」, 정지 버튼 자리에 「이어서」(▶)이고, 누르면 멈춘 자리부터 튼다. 플레이어를 다시 눌러 이어 틀어도 앱은 재생 중으로 돌아온다. 이어 틀면 끝 시각 정지(페이드 포함), 「응원가로」, 진행 막대가 그대로다. 일시정지 중 「응원가로」(`S`)는 응원가 시작으로 옮겨 이어 튼다. 일시정지 중 다른 곡을 누르면 그 곡을 튼다. 앱이 끝으로 줄이는(페이드) 중에 밖에서 멈추면 곡이 끝난 것으로 본다 |
| BR-63 | 일시정지 중에는 「정지」 버튼을 두지 않고, `Space`는 그 곡을 바로 끝낸다(재생 줄은 마지막 곡 「멈춤」이 된다). 일시정지는 이미 소리가 없어 버튼을 하나 더 둘 이유가 없다. `Space`는 경기 중 소리를 끄는 키라, 일시정지 중에 눌러도 소리를 내지 않아야 한다(이어 틀기로 쓰면 버릇대로 누른 `Space`에 소리가 다시 난다) |

## 10. AI 결과 검토 및 개선 기록

### 10.1 AI가 도출한 요구사항 중 적절하다고 판단해 그대로 둔 항목

- 원본 데이터 조사(1.5절): 요구사항을 쓰기 전에 10개 영상 설명란을 실제로 읽어 형식, 구획, 선수 수, 중복, 없는 정보를 확인한 것
- 곡 종류 자동 분류 규칙(BR-13)과 상황 곡 중복 제거(BR-14): 10개 영상 모두 마지막 구분선 뒤가 팀 응원가이고 선수 제목이 두 형식뿐이라 규칙이 단순하게 맞는다
- 가져오기의 "후보 확인 → 저장" 단계(BR-08)와 같은 곡 "이미 있음" 표시(BR-15)
- 재생 규칙(BR-01~06): 한 번에 한 곡, 다시 누르면 처음부터, 끝 시각에 멈춤, 팀을 바꿔도 재생 유지
- 전 팀 전환 규칙(BR-26~27)과 처음 실행 처리(BR-28)
- API 키 없음·할당량 초과·네트워크 끊김·재생 오류·저장 데이터 손상 예외(EX-06~15)와, API가 안 돼도 재생·관리 기능은 계속 동작한다는 원칙
- 팀 응원가 목록(FR-08): 사용 장면에는 없었지만 데이터에 팀당 17~29곡이 있다
- 정지 버튼(FR-09)
