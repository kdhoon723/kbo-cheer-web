# 1. 데이터 조사 정정
직접 다시 세어 보니 선수 235명, 등장곡만 16명은 맞았다. 그런데 두산 영상(jHxEtjKhJvA) 설명란에 시각이 거꾸로 가는 줄이 있다.
`39:15 챔피언 두산` 바로 다음 줄이 `30:36 서울 두산 승리하리라`다. 오타로 보인다.
- 1.5절의 "예외 형식 0건"을 고치고, 다른 9개 영상도 시각이 앞 줄보다 같거나 작은 줄이 있는지 확인해 결과를 적어라.
- 예외 처리에 추가: 시각이 거꾸로 가는 줄은 후보 표에 경고와 함께 표시하고 기본 선택을 풀어 둔다. 사용자가 확인 단계에서 시각을 고치면 정상 후보가 된다. 그 앞 곡의 끝 시각도 이 줄 때문에 틀어지지 않게 한다.

# 2. 검색 범위 변경
검색은 현재 팀만이 아니라 10개 구단 전체에서 찾는다. 게임 중에는 상대 팀 선수 곡을 찾을 때가 많다.

- 다른 팀 곡을 누르면 그 팀으로 바꾸고(BR-22 그대로) 바로 재생한다.

# 3. 미결 사항 결정

- D-02: (b) 채택. 수정 화면 입력 + 재생 중 「지금 위치를 응원가 시작으로」 버튼.
- D-03: (a) 채택. 상황 버튼은 등록된 상황 곡으로만 만든다. 사용 장면의 "아웃"은 예시였으니, 문서에서는 데이터에 실제로 있는 상황(풀카운트, 볼넷, 안타 등)으로 바꿔 써라.
- D-04: (a) 채택. 처음 데이터를 만들 때 확인 단계에서 바로잡는다.

# 4. 추가 제안 결정
- 채택: P-01 JSON 내보내기·가져오기, P-02 처음 데이터로 되돌리기, P-04 키보드 단축키, P-05 볼륨 조절과 페이드아웃, P-06 구단 색상, P-07 격자 정렬 바꾸기. 기능 요구사항으로 옮기고 ID와 수용 기준을 붙여라.
- 미채택: P-03 타순과 「다음 타자」. 실제 게임에서는 대타·교체로 타순이 자주 바뀌어 앱 타순을 고치느라 오히려 손이 더 간다. 격자와 검색이면 충분하다.
- 미채택: P-08 PWA. 서버를 로컬로 돌려 휴대폰은 http LAN 주소로 접속하는데, 홈 화면 설치에 필요한 서비스 워커는 HTTPS(또는 localhost)에서만 동작한다.

## 2. STEP 2 설계 (2026-11-15)

# 역할
너는 React와 TypeScript 기반의 프론트엔드 소프트웨어 설계 전문가이다.

# 프로젝트
확정한 docs/requirements.md(FR-01~28)를 바탕으로 KBO 응원가 즉시 재생 웹서비스의 상세 설계를 수행하라.

# 기술 환경
- React, TypeScript, Vite (dev 서버 포트 5173 고정, LAN 접속 허용)
- YouTube IFrame Player API, YouTube Data API v3(videos.list, search.list)
- LocalStorage
- CSS (UI 라이브러리 없음)
- React Router (수업에서 배운 중첩 라우트, useParams)

# 설계 작업
1. 곡(Song), 팀(Team), 가져오기 후보(ImportCandidate), 설정 등 데이터 모델을 설계한다.
2. TypeScript interface 또는 type을 정의한다. any는 쓰지 않는다.
3. 곡 목록·팀 상태·설정의 저장 구조를 설계한다. LocalStorage 키, 저장 형식의 버전, 읽을 때 형식 검사와 깨진 데이터 복구 방법을 포함한다.
4. 설명란 파싱과 자동 분류 알고리즘을 설명한다. 시각이 거꾸로 가는 줄 처리, 같은 상황 곡 중복 제거, 끝 시각 계산을 포함한다.
5. 화면 구성과 사용자 동선을 설계한다(메인 화면, 곡 관리·수정, 가져오기, 설정). 라우트 구조를 정한다.
6. React 컴포넌트 계층 구조를 작성하고 컴포넌트별 책임과 Props를 정의한다.
7. 상태 관리 구조를 설계한다. 곡 목록은 수업에서 배운 useReducer + Context 구조(액션: 등록, 수정, 삭제, 가져오기 저장, 전체 바꾸기)로, 재생 상태는 별도 Context로 둔다. 어떤 상태를 어느 컴포넌트에 두는지와 그 이유를 적는다.
8. YouTube 플레이어 연동을 설계한다. 스크립트 로드, 플레이어 하나를 재사용하는 방법, 구간 재생과 끝 시각 정지, 응원가로 이동, 페이드아웃, 오류 코드 처리, 컴포넌트가 사라질 때 정리(cleanup)를 포함한다.
9. 초성 검색 알고리즘과 10개 구단 전체 검색의 정렬 방법을 설명한다.
10. Data API 호출 모듈과 오류 분류(키 없음, 키 무효·리퍼러 불일치, 할당량 초과, 네트워크)를 설계한다.
11. 처음 데이터(JSON)를 가져오기 기능으로 만드는 절차를 정한다.
12. 요구사항 ID와 설계 요소를 잇는 추적표를 만든다.

motion 라이브러리(npm `motion`, React는 `motion/react`, 정확한 버전으로 고정)로 움직임을 넣는다.

# 모션 원칙
움직임은 누른 일을 확인하고 그것이 어디서 왔는지 보여 줄 뿐이다.

# 어디에 무엇을
- 누름: 1px 선으로 붙은 칸(선수 칸, 상황 칸, 목록 줄)은 칸과 선은 그대로 두고 안의 글자만 0.96으로 줄어든다(선이 흔들리면 격자가 깨져 보인다). 혼자 선 버튼(정지, 응원가로, 전 팀 등)은 버튼 전체가 줄어든다. 들어갈 때 tap, 풀릴 때 spring.press. 재생 중 칸의 반전은 움직이지 않고 바로 바뀐다.
- 팀 전환: 선수 격자와 팀 응원가 목록이 팀 순서에서 새 팀이 있는 쪽에서 24px 들어오며 swap으로 나타난다. 「전 팀」으로 두 팀을 오가면 늘 반대쪽에서 온다. 나가는 목록은 그 프레임에 사라진다. 머리의 팀 이름, 검색칸, 탭, 상황 격자는 움직이지 않는다(손이 외운 자리를 흔들지 않는다).
- 목록 첫 등장: 검색 결과가 처음 나타날 때, 곡 관리·가져오기 후보 목록이 처음 열릴 때 항목이 아래 8px에서 24ms씩 차례로 올라온다(9번째부터는 8번째와 함께). 이미 열린 목록에서 검색어를 더 칠 때는 움직이지 않는다.
- 팀 시트·메뉴: spring.sheet로 올라오고 뒤 막은 swap으로 짙어진다. 닫을 때는 exit.
