## 3. 성능 측정

측정 방법:
- 브라우저 콘솔에서 버튼의 `click()`을 부른 순간부터 시간을 잼.
- 20ms마다 `YT.get('yt-player')`로 상태와 위치를 읽음.
- "상태 PLAYING이고, 위치가 새 곡 시작 시각부터 2초 안"이 처음 된 때까지를 응답 시간으로 봄.
- 화면 1280×800, 노트북 브라우저 1개, 측정 직전에 같은 페이지에서 실제 클릭으로 한 곡을 재생해 둠.

### 3.1 NFR-03 재생 시작 응답(목표: 2초 안)

| 구분 | 10회 측정값(ms) | 중앙값 | 최댓값 | 실패 |
| --- | --- | --- | --- | --- |
| 같은 영상 안 전환(한화 선수 10명, 앞뒤로 먼 순서) | 302, 262, 262, 261, 262, 282, 265, 261, 282, 244 | 262ms | 302ms | 0 |
| 다른 영상 전환(검색으로 삼성 디아즈 ↔ 한화 노시환 번갈아) | 284, 302, 245, 262, 266, 242, 262, 262, 249, 248 | 262ms | 302ms | 0 |

- 두 경우 모두 목표 2초 안이다.
- 측정 범위: 다른 영상 전환은 두 영상을 번갈아 불러서, 두 번째부터는 브라우저가 영상을 이미 받아 둔 상태였다. 새로 연 페이지의 첫 재생은 작성 중 E2E 실행의 TC-13 로그 기준 약 0.4초였다("누른 뒤 409ms", 1회 측정).
- 측정 범위: 서버 근처의 빠른 유선 네트워크에서 잰 값이다. 휴대폰 와이파이에서는 더 걸릴 수 있다.

## 4. 실패 목록(원인 분석·수정은 다음 단계)

### F-01 첫 재생에서 YouTube 플레이어가 재생을 시작하지 못함(간헐)

- 해당 TC: TC-13, TC-22(마지막 전체 실행), TC-22, TC-43(작성 중 실행). 모두 재실행하면 통과했다.
- 증상:
  · 새로 연 페이지에서 첫 곡을 누르면 플레이어 상태가 -1(시작 안 됨), 위치가 시작 시각에 머문다.
  · 앱은 "이 곡을 재생할 수 없습니다(브라우저 재생 오류)"를 띄우고 재생 패널을 "선택한 곡 없음"으로 되돌린다.
  · 이 문구는 YouTube가 `onError` 코드 5(HTML5 플레이어 오류)를 보냈을 때 나오는 안내다. 앱은 설계(EX-11)대로 안내하고 멈췄다.
- 재현 절차:
  1. 새 브라우저 컨텍스트(LocalStorage 비움)로 `http://localhost:5173/team/hanwha`를 연다.
  2. 플레이어가 준비되면 선수 버튼(예: 노시환)을 한 번 누른다.
  3. 대부분은 414초부터 재생되지만, 가끔 위 증상이 나온다.
- 빈도: E2E에서 페이지를 연 뒤 첫 재생을 하는 테스트 중 일부. 마지막 전체 실행은 47개 중 2개, 작성 중 실행도 47개 중 2개였다. 같은 테스트를 다시 돌리면 통과했다.
- 관찰한 근거:
  · 실패 화면 기록(`test-results/.../error-context.md`)에 위 안내 문구가 남아 있다.
  · 작업 중에 앱 코드 없이 IFrame API 플레이어만 띄운 임시 페이지를 25번 돌렸을 때도 2번 같은 식으로 재생되지 않았다는 기록이 있다. 이 임시 실험은 테스트 작성 과정에서 했고, 결과 문서를 쓰는 지금 다시 재현해 보지는 않았다.
- 판단 보류: 앱 버그인지 headless Chromium과 YouTube 사이의 환경 문제인지는 아직 결론 내지 않았다. 사용자가 같은 상황을 만나면 안내 문구를 보고 버튼을 다시 눌러야 한다.

### 8.1 F-01과 첫 재생 시간 비교

같은 서버(Chromium headless, 360×640)에서 바꾸기 전 코드와 바꾼 코드를 10번씩 묶어 번갈아 돌렸다. 새 창마다 첫 선수 칸을 누르고, 페이지 안의 click 이벤트부터 PLAYING까지를 쟀다. 8초 안에 재생되지 않으면 실패로 셌다.

| 비교 | 횟수 | 실패 | 중앙값 | 평균 | 90번째 백분위 | 최대 |
| --- | --- | --- | --- | --- | --- | --- |
| 모션 전 / 모션 후(`e2e/playback.spec.ts` 12개 × 4회) | 48 / 48 | 5 / 2 | - | - | - | - |
| 디자인 개편 후속 전 / 후(첫 재생) | 80 / 80 | 9 / 7 | 308ms / 314ms | 335.0ms / 323.9ms | 385ms / 371ms | 814ms / 398ms |

- 모션 단계에서 MCP 브라우저(1280×800)로 잰 재생 시작 응답은 같은 영상 10회 중앙값 262.5ms(최대 322ms), 다른 영상 10회 중앙값 248ms(최대 272ms)다. STEP 4(3.1절)는 둘 다 중앙값 262ms, 최대 302ms였다.
- 두 비교 모두 바꾼 뒤가 더 나빠지지 않았다. F-01 빈도는 묶음마다 0~3번으로 흔들려서, 이 횟수로 어느 쪽이 낫다고 말할 수는 없다.
